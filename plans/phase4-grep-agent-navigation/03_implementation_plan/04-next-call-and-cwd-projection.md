# Stage 4: Next Recommended Call And CWD Projection

## Goal

Make grep outputs immediately actionable while preserving Phase 3 cwd path rules and no-leak guarantees.

## Depends On

- Stage 1 DTO/schema.
- Stage 3 file groups and read ranges.

## Touched Areas

- `filetoolsserver/handler/grep_tool.go`
- `filetoolsserver/handler/grep_rows.go`
- `filetoolsserver/handler/cwd_path.go`

## Recommendation Field

Add to `GrepOutput`:

```go
NextRecommendedCall *ActionHint `json:"next_recommended_call,omitempty"`
```

Use existing `ActionHint` shape.

Public JSON contract:

```json
{
  "safe_to_retry": true,
  "recommended_next_tool": "read_file",
  "recommended_next_input": {},
  "recommended_next_input_policy": "open_first_relevant_range",
  "reason": "Open the first bounded grep range for line-addressable context."
}
```

Field rules:

- `safe_to_retry` is required and is `true` for every Phase 4 grep recommendation because recommendations are read-only and bounded.
- `recommended_next_tool` is one of `read_file`, `grep`, or `outline_file`.
- `recommended_next_input` is the complete replayable input for that tool.
- `recommended_next_input_policy` is a short stable policy id.
- `reason` is concise, generated by the server, and must pass cwd path sanitization.

Every recommended `grep` must preserve or narrow the selected scope. It must never broaden a search that used `cwd_id`, `path`, filters, or `line_window`.

Recommended `grep` preservation matrix:

- always preserve `cwd_id` when present;
- always preserve `path`;
- always preserve `line_window` when present;
- always preserve `pattern`, `pattern_mode`, `case_insensitive`, `multiline`, `type`, `glob`, and `ignore_globs`;
- when keeping `output_mode="content"`, preserve `before`, `after`, and `context`;
- when switching from `content` to `files_with_matches`, intentionally drop `before`, `after`, `context`, and `max_matches_per_file` because those are content-only controls;
- when retrying literal or case-insensitive no-match searches, preserve original `output_mode`, `before`, `after`, `context`, `line_window`, `limit`, and `max_matches_per_file` when `output_mode` is empty/content;
- recommended `limit` defaults to the original input limit if present, otherwise the effective default limit used by the current call.

`ignore_globs` cwd safety:

- In cwd mode, recommended `grep` may preserve `ignore_globs` only when every entry is relative/glob-only and does not contain an absolute path or drive/UNC-looking prefix.
- Do not rewrite absolute-looking `ignore_globs` into relative globs, because that can change glob semantics.
- If a recommendation would otherwise need to preserve unsafe `ignore_globs`, omit `next_recommended_call`.
- Tests must cover a cwd-aware recommended `grep` with safe relative `ignore_globs` and a cwd-aware input with absolute-looking `ignore_globs` where the recommendation is omitted.

## Recommendation Policy

Recommendation must be deterministic.

Definitions:

- A file dominates content output when it owns at least 80% of returned match rows and has at least 5 returned match rows.
- A complete file group is dense enough for `outline_file` when it has at least 8 logical matches or its returned evidence spans at least 120 lines.
- A conservative generated `max_matches_per_file` is `min(current limit, max(3, floor(current limit / 5)))`; for low limits this yields `1` when `limit=1` and `2` when `limit=2`.
- A useful read range is a non-empty `read_ranges[0]` with `end_line >= start_line`.
- A regex-looking pattern is one that contains at least one unescaped regex metacharacter from `. ^ $ * + ? ( ) [ ] { } |` and does not contain whitespace-only content.

Regex-looking predicate algorithm:

- Scan the pattern left to right.
- For each character in `. ^ $ * + ? ( ) [ ] { } |`, count consecutive backslashes immediately before it.
- If that count is even, the metacharacter is unescaped and the predicate is true.
- If that count is odd, the metacharacter is escaped and does not trigger literal retry.
- A backslash by itself does not trigger literal retry; this avoids recommending literal mode for already-escaped regex patterns.
- Examples that trigger: `foo.bar`, `func(`, `a[bc]`, `value|other`.
- Examples that do not trigger: `foo\\.bar`, `func\\(`, `a\\[bc\\]`, `plain text`, `C:\\temp`.

Case-insensitive retry usefulness predicate:

- Recommend `case_insensitive=true` only when the pattern contains at least one ASCII letter `[A-Za-z]`.
- Do not recommend case-insensitive retry for numeric-only, punctuation-only, whitespace-only, or path-separator-only patterns.
- Examples that may trigger when no higher-priority retry applies: `todo`, `HTTP`, `handler42`.
- Examples that do not trigger: `123`, `[]()`, `...`, `/tmp/path`.

When multiple file groups satisfy the same recommendation rule, choose deterministically:

- use `file_groups` order for first-range `read_file`;
- for dense `outline_file`, choose the earliest group in `file_groups` order among groups that meet the threshold;
- if an implementation computes candidates outside the final array, tie-break by first returned evidence order, then slash-normalized path ascending.

Priority:

1. If output was globally truncated (`search_stats.stop_reason="limit"`) and the selected scope can still benefit from file-diversity mapping, recommend a same-or-narrower `grep` before any `read_file`:
   - preserve `pattern`, `pattern_mode`, `case_insensitive`, `type`, `glob`, `ignore_globs`, `multiline`, and cwd context;
   - if current mode was `content` and one file dominated while `max_matches_per_file` was absent, keep `output_mode="content"` and include a conservative `max_matches_per_file`;
   - otherwise, if current mode was `content`, prefer `output_mode="files_with_matches"` to map files before opening ranges;
   - if current mode was `files_with_matches` or `count`, omit `next_recommended_call` unless the server can provide a same-or-narrower filter without inventing semantic meaning from path names;
   - use this mapping/narrowing path only when the original resolved search scope was a directory or otherwise produced multiple file groups/files; do not recommend it for an already-known single-file scope or a single-file `line_window`;
   - do not recommend a plain higher `limit` retry as the primary next action;
   - never combine `output_mode="files_with_matches"` or `output_mode="count"` with `max_matches_per_file`;
   - policy id: `narrow_truncated_grep`.
2. If output was globally truncated and the selected scope is already a single file or single-file `line_window`, skip redundant mapping and fall through to the structural/range inspection rules below using returned evidence:
   - dense group can recommend `outline_file`;
   - otherwise first useful `read_ranges[0]` can recommend `read_file`;
   - policy ids remain `inspect_file_outline` or `open_first_relevant_range`.
3. If output hit a per-file cap (`search_stats.stop_reason="file_cap"`) and the selected scope can still benefit from file-diversity mapping, recommend a mapping/narrowing `grep` before any `read_file`:
   - prefer `output_mode="files_with_matches"` for the same selected scope;
   - omit `max_matches_per_file` in that recommended mapping call;
   - use this only when the original resolved search scope was a directory or otherwise produced multiple file groups/files; do not recommend this for an already-known single-file scope or a single-file `line_window`;
   - policy id: `map_capped_grep_files`.
4. If output hit a per-file cap and the selected scope is already a single file or single-file `line_window`, skip mapping and fall through to the structural/range inspection rules below using returned evidence:
   - dense group can recommend `outline_file`;
   - otherwise first useful `read_ranges[0]` can recommend `read_file`;
   - policy ids remain `inspect_file_outline` or `open_first_relevant_range`.
5. If output is complete or single-file truncated/capped fallback is active, and one file group is dense enough that structural context is more useful than opening the first small range, recommend:
   - tool: `outline_file` for that file;
   - include `line_window` when the chosen file group has valid `first_line` and `last_line`;
   - construct that `line_window` as `{ "start_line": first_line, "end_line": last_line }`, with `start_line` clamped to at least `1` and both endpoints clamped to the original input `line_window` when one was used;
   - omit the outline recommendation if the dense group has no valid line coordinates after clamping;
   - policy id: `inspect_file_outline`.
6. If output is complete or single-file truncated/capped fallback is active, and has a useful `file_groups[0].read_ranges[0]`, recommend:
   - tool: `read_file`;
   - input path field: `target_file`;
   - start/end from read range;
   - `cwd_id` included when cwd mode was used.
   - policy id: `open_first_relevant_range`.
7. If no matches, the search is complete (`completed=true`, `counts_are_complete=true`, and `stop_reason=""`), pattern mode is regex, and pattern contains common regex metacharacters that might have been intended literally, recommend:
   - tool: `grep`;
   - same input but `pattern_mode="literal"`.
   - policy id: `retry_literal_pattern`.
8. If no matches, the search is complete (`completed=true`, `counts_are_complete=true`, and `stop_reason=""`), `case_insensitive=false`, and the case-insensitive usefulness predicate passes, recommend `case_insensitive=true` only if literal/regex retry is not already a better recommendation.
   - policy id: `retry_case_insensitive`.
9. If no clear useful next step, omit `next_recommended_call`.

Only one top-level recommendation is allowed.

## Recommended Input Shape

For `read_file`:

```json
{
  "cwd_id": 1,
  "target_file": "path/from/cwd.go",
  "start_line": 10,
  "end_line": 30
}
```

For `grep`:

```json
{
  "cwd_id": 1,
  "pattern": "needle",
  "pattern_mode": "literal",
  "path": ".",
  "type": "go",
  "output_mode": "files_with_matches",
  "limit": 50
}
```

For `outline_file`:

```json
{
  "cwd_id": 1,
  "target_file": "path/from/cwd.go",
  "line_window": {
    "start_line": 10,
    "end_line": 80
  }
}
```

## CWD Projection

Extend `sanitizeGrepOutput`:

- sanitize `FileGroups[].Path`;
- sanitize every path in `NextRecommendedCall.RecommendedNextInput`;
- add `cwd_id` to recommended inputs when input had cwd mode;
- preserve literal `pattern` and content text unchanged.

Use existing `sanitizeActionHint` / `sanitizeRecommendedInput` where possible. If new nested recommended input shapes appear, extend shared sanitizer rather than writing grep-only string replacement.

## No-Leak Fields

When cwd mode is used, these must not contain absolute paths:

- `path`;
- `matches[].path`;
- `files[]`;
- `counts[].path`;
- `file_groups[].path`;
- `next_recommended_call.reason`;
- `next_recommended_call.recommended_next_input.path`;
- `next_recommended_call.recommended_next_input.target_file`;
- `next_recommended_call.recommended_next_input.ignore_globs[]` when present;
- any generated message, not including content text or user-supplied pattern.

`cwd` is the only absolute path field allowed in cwd-aware successful output.

No-leak JSON tests must inspect generated path/message/reason/recommended-input fields. They must not scan `matches[].text` or the user-supplied `pattern` for the cwd string, or must use fixtures whose content/pattern cannot contain the absolute cwd path.

## Schema

Ensure `ApplyPathOutputSchemaConstraints` marks:

- `file_groups[].path`;
- recommended input path fields under `next_recommended_call`.

If existing recursive schema walking covers these fields, add regression tests anyway.

## Tests

- cwd grep content result has relative `file_groups[].path`.
- cwd `next_recommended_call` for `read_file` includes `cwd_id` and relative `target_file`.
- no absolute root appears in generated cwd-aware grep output JSON except `cwd`.
- no-cwd output remains slash-normalized absolute/display.
- recommended `grep` retry preserves safe input fields.
- cwd recommended `grep` preserves safe relative `ignore_globs`.
- cwd recommended `grep` is omitted when preserving `ignore_globs` would leak an absolute path.
- truncated noisy multi-file/directory content result recommends narrower `grep`, not first `read_file`.
- truncated single-file or single-file `line_window` content result skips redundant mapping and falls through to `outline_file`, `read_file`, or no recommendation according to returned evidence.
- capped multi-file/directory content result recommends mapping/narrowing `grep`, not first `read_file`.
- capped single-file or single-file `line_window` content result skips redundant mapping and falls through to `outline_file`, `read_file`, or no recommendation according to returned evidence.
- no-match literal retry recommendation works and does not mutate pattern text.
- one recommendation only.
- `next_recommended_call.reason` has no cwd absolute path leak.

## Stop And Ask If

- Recommendation policy would require semantic code understanding.
- Sanitizing a new nested path field cannot be handled by shared projection.
